# 红队记录：可能的反驳与回应

## 反驳 1：`valution` 只是工具调用错误，不是“语言”

**回应**：本文不把 `valution` 当作自然语言词，而是当作工具语法层的词形。它满足词形的三个条件：可重复、可组合、可扩散；它还发生了语义漂白（absorbing subagent/job/product/empty schemas）。即使它是“错误”，它也是语言系统的一部分——错误词形同样会被上下文强化、被其他 Agent 模仿、消耗预算。把它排除，反而会漏掉最重要的病理机制。

## 反驳 2：`逐字`、`收口` 可能是模型的一般词汇，不是“涌现”

**回应**：我们区分“新造词”和“提示词之外的 convention”。`逐字` 可能来自模型的一般中文能力，但它在系统里获得了稳定的语用功能（要求逐字符证据、禁止转述），并且从 parser 扩散到四个 Agent。论文用“extralexical operational term”而不是“neologism”，正是为了避免过度主张。9 个与种子文本重叠的词也单独标注。

## 反驳 3：行话密度与 rounds 的相关只是“难任务说得更多”

**回应**：我们同意，并在正文明确说“行话密度是难度/争议指标，不是能力指标”。Poisson 回归控制派工 token 后系数仍为正（0.208，p=0.019），但这不是因果。我们把它作为“标记”而非“原因”。

## 反驳 4：收敛结果可能是采样噪声

**回应**：我们用了 pooled null 和 bootstrap CI；12 小时窗 main–reviewer p=0.015（q=0.09，边缘），24 小时窗 p=0.007（q=0.021）。main–parser 不显著，parser–reviewer 略分化。我们只报告稳健的部分，并明确 12h 的边缘性。

## 反驳 5：分类器 main F1 只有 0.332，说明“角色方言”不成立

**回应**：角色方言不需要“每个角色都可分”。我们的结论是“梯度”：Watchdog 高度可分（0.932），parser/reviewer 中度（0.651/0.698），main 是拼装体（0.332）。这恰好说明主 Agent 的语域由子 Agent 词汇 + 调度词汇构成，而不是一个独立的纯语域。分类器的混淆矩阵本身就是证据。

## 反驳 6：主会话历史缺失 48.7%，首现归因不可靠

**回应**：我们承认，并把 child-first 称为“上界”。早主 Agent 的语言通过 756 条 parser 派工、676 条 reviewer 派工保留；这些派工是主 Agent 写的，能支持“主 Agent 早期用词”的分析。论文在 4.7 和 8.2 明确说明。

## 反驳 7：产品脱敏后，案例不可复核

**回应**：案例保留 message_id、session_id、UTC 时间、Agent 角色；内部读者可用源库复核。公开读者只能核对聚合数字和脱敏片段。这是内部研究数据的必要折中；`data/private/` 保存完整映射，但不公开。

## 反驳 8：结果数量不等于财务正确

**回应**：同意。本文的“成功”是流程完成/激活，不是财务审计。论文 8.6 明确说明；语言与财务正确性的关系需要另一项研究。

## 反驳 9：`valution` 2,271 次连续调用可能是 harness 重试，不是模型行为

**回应**：我们检查了 message_id：2,271 次是 2,271 条独立 assistant 消息，每条一个 tool part，输入 schema 随时间变化（agent → job_id → product_id → empty），不是同一条消息的自动重试。平均间隔 0.98 秒，跨 9 小时。即使 harness 有重试，词形和 schema 的变化也说明模型在生成不同意图；我们只把“连续 run”作为描述，不假设每一次都是独立理性决策。

## 反驳 10：`cost=0`，所以“2.49 亿 token”没有经济意义

**回应**：token 是协调带宽的代理，不是美元成本。我们明确说 `cost=0` 是 provider 未配置价格；token 仍能说明上下文占用和推理负担。不同 provider 的价格会改变“值不值得”的结论，但不改变“2,271 次无效调用”的事实。
